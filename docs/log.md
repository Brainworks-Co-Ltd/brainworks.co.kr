# BrainWorks 문서 지식 변경 로그

## 2026-08-25

### 완료

- 공지사항 상세의 공개 첨부파일 조회와 다운로드 API 연결을 구현했습니다.
- 관리자 공지사항과 팝업 공지 목록이 초안 및 게시 중단을 포함한 운영 상태를 보여주도록 보완했습니다.
- 팝업 공개 쿼리가 예약 게시 시각과 공개 후보 최대 3건을 실제로 판정하도록 수정했습니다.
- 계정 설정 화면에 기능이 추후 개발 예정임을 표시했습니다.
- 타입 검사, 린트, 관련 테스트 8개, 프로덕션 빌드를 통과한 검증 증빙을 추가했습니다.

### 미해결

- 실제 객체 저장소 첨부파일 다운로드와 관리자 브라우저 E2E는 운영 환경 정보가 필요한 검증으로 남아 있습니다.

## 2026-08-24

### 제안

- 공개 내비게이션 중앙 모델, 데스크톱·모바일 탐색, PageHero 변형, 자산 승인 관문과 최소 회귀 검증을 다섯 체크포인트로 나눈 구현 계획을 작성했습니다.
- shadcn/ui와 Lucide 통합 구현 계획을 작성하고 파일·테스트·커밋 단위 검토를 요청했습니다.

### 결정

- 공개 Header를 회사소개·사업 영역·소식 메뉴 그룹과 문의하기 직접 행동으로 계층화하고, 홈은 로고로만 이동하도록 확정했습니다.
- 사업 영역 아래에 AI 솔루션·AI 컨설팅·AI 전문교육·글로벌 프로그램을 묶되 새 `/business` 랜딩 페이지는 만들지 않기로 했습니다.
- 공개 PageHero를 사업용 `media`, 회사 정보용 `split` 또는 정적 `media`, 읽기·입력용 `plain`으로 구분하고 승인 자산이 없으면 단색 표면을 사용하기로 했습니다.
- shadcn/ui를 공개 페이지의 시각 레퍼런스가 아닌 상호작용·접근성 기반으로 도입하고, 기존 `--bw-*` 디자인 토큰을 원본으로 유지하는 통합 설계를 승인했습니다.
- Lucide를 기능·상태 아이콘 표준으로 정하고 문자 기호와 직접 SVG를 실제 사용처 단위로 점진 전환하도록 확정했습니다.
- 첫 적용 범위를 기반 설정, Button·Dialog 전환, Carousel 조작 아이콘 전환으로 제한하고 사용처 없는 컴포넌트 선설치는 제외했습니다.

### 완료

- MakinaRocks식 공개 사업 영역 메가메뉴를 승인된 기존 사업 영역 이미지와 실제 서비스 라우트로 구현하고, 데스크톱·모바일 계층 회귀 검증을 완료했습니다.

- 기존 구현 증빙 9개와 레퍼런스 공개 레이아웃 계획에 Wiki 머리말과 인덱스 진입점을 보완해 `docs/**/*.md` 48개 전체 lint를 통과했습니다.
- 기존 전체 구현 계획의 평면 1차 메뉴와 두 유형 PageHero 요구를 최신 공개 내비게이션·Hero 계획으로 교체했습니다.
- 공개 내비게이션 중앙 모델, 계층형 Header·Footer·모바일 메뉴, PageHero 변형과 승인 전 `plain` 관문을 구현하고 5개 공개 경로를 프로덕션 빌드에서 검증했습니다.
- 공개 내비게이션·PageHero 구현의 자동 검사 15개, TypeScript 검사, Next.js 프로덕션 빌드를 통과한 증빙을 추가했습니다.

## 2026-08-23

### 결정

- `docs/**/*.md`를 LLM Wiki의 유일한 지식 원본으로 사용합니다.
- Karpathy의 방법에 따라 주제별 진입점인 `docs/index.md`와 시간순 기록인 `docs/log.md`를 함께 운영합니다.
- Graphify는 문서를 대신 생성하지 않고 문서 사이의 관계를 추출하고 지식 지도를 만드는 역할만 담당합니다.
- 앞으로 추가되는 `docs` 파일은 `.gitignore`로 숨기되 기존 추적 문서는 계속 추적합니다.
- Graphify 입력은 `docs/**/*.md`로 제한하고 탐지에서 `gitignore=False`를 강제합니다.
- 홈페이지의 제품 역할을 `검증 가능한 브랜드 신뢰를 거쳐 적합한 B2B 문의로 연결`하는 것으로 정하고, 브랜드 전시형과 전환 우선형을 결합한 신뢰 기반 문의 혼합형을 채택했습니다.
- 우선 사용자는 AI 공급자를 검토하는 기업·기관 사업 책임자를 구조 구현용 가설로 두고, 최종 문구와 서비스 우선순위는 실제 업무 담당자 확인 후 확정하기로 했습니다.
- 콘텐츠 운영은 관리자 한 명과 단일 `ADMIN` 역할로 시작하며, 기준선이 없는 성공 수치는 만들지 않고 출시 후 개인정보 없는 수동 문의 집계로 먼저 확인하기로 했습니다.
- AS-IS·TO-BE와 에픽·사용자 스토리를 담은 홈페이지 제품 기획을 사용자 승인 상태로 확정했습니다.
- 대표님 요구인 공지사항 게시판과 홈 팝업 공지를 서로 다른 도메인으로 두고 선택적으로만 연결하기로 승인했습니다.
- 팝업은 비모달·로케일별 최대 3건·모바일 한 건씩 수동 탐색으로 제공하고, 방문자가 닫기 전까지 유지하기로 했습니다.
- 공지 첨부는 비공개 객체 저장소에서 격리·검사한 뒤 공개 상태를 확인한 제한 시간 다운로드로 제공하기로 했습니다.
- 새 공지 기능에서는 방문자 `닫기`와 관리자 `게시 중단`을 구분하고 영구 삭제 UI를 두지 않기로 했습니다.

### 완료

- LLM Wiki와 Graphify 통합 설계를 승인 상태로 변경했습니다.
- 기반 구축 계획과 기존 문서 전환·최초 지도 생성 계획을 작성했습니다.
- `.gitignore`에 `/docs/**`와 `/graphify-out/` 규칙을 추가하고 기존 추적 문서 네 개가 유지되는지 확인했습니다.
- Graphify `graphifyy==0.9.48`을 사용자 Python 영역에 설치했습니다.
- 공식 Graphify 스킬과 BrainWorks 전용 `brainworks-docs-wiki` 스킬을 설치했습니다.
- Markdown 인벤토리·lint 검사기와 Graphify Markdown 전용 탐지 어댑터를 구현했습니다.
- Graphify 탐지 캐시가 `docs/graphify-out`에 생기는 부작용을 재현하고, 시스템 임시 캐시로 분리하는 회귀 테스트와 수정을 적용했습니다.
- 스킬 적용 전후 압력 시나리오를 기록하고, 구조 검증과 단위 테스트를 수행했습니다.
- 이 인덱스와 변경 로그를 생성했습니다.
- 기존 업무 문서 19개에 Wiki 역할, 검토 상태, 원문에서 확인된 선행 문서 관계를 추가했습니다.
- `docs` 밖 Markdown 문서로 향하던 링크 한 건은 경로 표기를 유지한 일반 코드 표기로 바꾸고, 전체 Wiki lint를 통과했습니다.
- Graphify `0.9.48`로 `docs/**/*.md` 25개만 탐지하고, 저장소 밖 임시 위치에서 지도를 생성·검증한 뒤 `graphify-out`으로 승격했습니다.
- 최초 지도는 노드 42개, 문서에 명시된 관계 44개, 커뮤니티 8개로 구성되며, 모든 출처가 `docs` 아래 Markdown인지 확인했습니다.
- 시각화 HTML, Graphify Wiki, Obsidian 내보내기는 생성하지 않았습니다.
- 사용자가 제공한 약 이틀 전의 외부 레퍼런스 조사 답변을 MakinaRocks, Upstage, Nota AI, Faculty, LandingAI, DeepLearning.AI 공식 페이지에서 다시 확인했습니다.
- 기존 조사 결론을 전면 변경하지 않고 핵심 방향을 유지했으며, LandingAI는 현재 공식 페이지에서 직접 확인되는 문서 처리·추적성·보안·배포 중심 표현으로 정밀하게 보정했습니다.
- 외부 사이트에서 확인한 사실, 브레인웍스 적용 판단, 적용하면 안 되는 요소, 내부 자료가 필요한 미해결 항목을 `planning/02-external-benchmarking.md`에 편입했습니다.
- 개발 문서 목차, 페이지별 개선 방향, Wiki 인덱스에서 외부 벤치마킹 근거를 연결했습니다.
- 홈페이지 개편에 필요한 회사 정보, Hero, 솔루션, 컨설팅, 교육, 글로벌 네트워크, 고객·파트너, 수상·인증, 뉴스, 개인정보와 자산 권리를 저장소 기준으로 감사했습니다.
- 파일 존재와 회사의 공개 승인을 분리하고, 확인되지 않은 사례·관계·이미지는 생성형 AI로 보완하지 않는 게시 관문을 정리했습니다.
- 멘토님께 바로 보낼 수 있는 자료 요청 메시지와 사실·자산별 회신 양식을 작성했습니다.
- `office-hours`와 `grill-me` 질의를 통해 대표님의 포괄적인 개선 요청, 저장소 사실, 영문 사이트 발견성 관련 내부 전언과 검증 가설을 구분했습니다.
- 홈페이지 개편의 AS-IS, TO-BE, 성공 정의, 제품 출시 필수성, 8개 에픽, 사용자 스토리와 인수 조건을 `planning/07-homepage-product-strategy-as-is-to-be.md`에 정리했습니다.
- 독립 기획 검토에서 사실·가설 표현, 측정 범위, 사용자 가설과 에픽 우선순위를 보정했으며 P0·P1 지적 없이 승인 판정을 받았습니다.
- 공지사항·팝업 공지 승인 명세와 별도 구현 계획을 작성하고, 라우팅·공개 구성·관리자·데이터·ERD·아키텍처·저장소·멘토 요청·전체 명세·전체 구현 계획에 교차 반영했습니다.
- 기존 입찰공고 제거 결정은 유지하고 새 공지사항·팝업 공지로 자동 이전하지 않도록 문서 전반에 명시했습니다.
- 사용자의 시각 자료 제외 결정을 따라 새 와이어프레임·ERD 이미지·다이어그램은 만들지 않았습니다.
- 승인된 공지 라우트와 접근 가능한 `소식` 하위 메뉴를 중앙 라우트 계약에 추가하고, 공지 스키마 소유권을 별도 수직 슬라이스로 단일화했습니다.
- 팝업 공개 기간·표시 순서를 로케일 행의 책임으로 통일하고, 같은 로케일 카테고리 이름과 게시 로케일별 필수 팝업 제목을 게시 조건으로 확정했습니다.
- 문서 검사 포트, 운영·테스트 어댑터, 악성·정상·시간 초과 처리와 스테이징·출시 관문을 전 기술 문서와 구현 계획에 교차 반영했습니다.
- 독립 재검토에서 이전 지적 여섯 항목이 모두 해소됐고 P0·P1·P2 추가 지적 없이 최종 승인됐습니다.
- LLM Wiki 재감사에서 콘텐츠 구조와 ERD의 남아 있던 `review` 상태를 승인 결과에 맞게 정정하고, 공지 기능 확장 로케일 열·공개 판정식을 ERD에 명시했습니다.

### 참고

- 현재 Codex 하위 에이전트 인터페이스가 정확한 의미 추출 토큰 사용량을 제공하지 않아 `graphify-out/cost.json`에는 측정 불가 상태와 0을 함께 기록했습니다.
